**Scope:** GLOBAL  
**Created:** 2026-07-26  
**Status:** APPROVED  
**Purpose:** 將人體工學、使用邏輯、故事進度一致性，以及每次生成前必須重新讀取 GitHub Master 規範的要求，納入全域製片流程。

## 1. Pre-Generation Verification Gate

任何 Keyframe、圖片或影片素材生成之前，必須先完成以下驗證；未完成不得生成：

1. 讀取 GitHub 最新版 MASTER／SOP／LOCK／APPROVED 文件。
2. 讀取當集最新 Story Lock、Visual Bible、Storyboard Master Sheet 與 Production State。
3. 確認 Character Lock、Scene Lock、Prop Lock、Exact Asset Lock。
4. 確認目前 Keyframe 的 Story Function、Generation Dependency 與版本號。
5. 讀取最新版 QC Checklist，包含本文件新增的 QC-07 與 Story Stage Check。
6. 任何聊天內容若與 GitHub 最新 LOCK／MASTER 衝突，以 GitHub 最新版本為準。
7. GitHub 讀取失敗時，不得假裝已完成驗證；必須先回報具體錯誤並停止正式生成。

## 2. QC-07｜人體工學與使用邏輯檢查

任何關鍵影格進入 APPROVED 前，必須通過以下檢查：

### 2.1 螢幕與設備方向

- 電腦、筆電、工作站、平板與手機螢幕必須朝向實際操作者。
- 鏡頭若位於操作者對面，原則上只能看見設備背面或合理的側面角度。
- 不得為了讓觀眾看清楚畫面，而讓螢幕不合邏輯地朝外。
- 若劇情需要展示螢幕內容，應改用合理的 over-the-shoulder、側後方或插入鏡頭，不得破壞操作邏輯。

### 2.2 文件、筆記本與書寫方向

- 筆記本、書本與文件必須朝向人物本人，符合閱讀與書寫方向。
- 不得為了讓觀眾看字，而把筆記本倒轉朝向鏡頭。
- 筆握、手腕、坐姿、視線與紙面位置必須一致。
- 思考階段只呈現少量關鍵字或草稿，不得提前出現完整成果型內容。

### 2.3 手機與攝影行為

- 自拍、觀看、拍攝、直播與剪輯時，手機鏡頭及螢幕方向必須符合真實使用方式。
- 手機不得無支撐漂浮；若使用腳架，腳架與手機固定方式必須合理。
- 人物視線必須對應正在使用的手機或鏡頭位置。

### 2.4 桌面與道具

- 鍵盤、滑鼠、杯子、筆、文件及其他道具不得妨礙人物操作。
- 道具位置與方向須延續前後 Keyframe，不得任意更換型號、顏色或位置。
- 同一段落已鎖定的設備不得自行由工作站改為筆電，或由筆電改為其他設備。

### 2.5 QC 判定

只要出現任一人體工學、設備方向、視線或使用邏輯錯誤，該素材必須判定為：

**REGENERATE**

不得以 APPROVED、LOCKED 或 FINAL 通過。

## 3. Story Stage Check｜故事進度一致性

每張影格必須只呈現當前故事階段應該發生的內容：

- 靈感／思考階段不得提前出現大量按讚、留言、播放量、成交或成功成果。
- 行動階段必須清楚呈現人物開始執行，而不是仍停留在思考。
- 成果與客戶回應只能在 Storyboard 指定的後續節點出現。
- 視覺效果不得取代 Story Function，也不得自行新增或改寫已鎖定劇情。

## 4. Exact Asset Rule

- 官方 Logo、品牌文字、QR Code 與指定原始素材均屬 EXACT ASSET。
- 生成式 AI 不得自行重繪、近似重製或替換官方 Logo。
- 未提供可正確置入的原始資產時，畫面應保留乾淨位置，並於後製加入。
- 任何 AI 自行生成的近似 Logo 均不得 APPROVED。

## 5. GitHub Sync Rule

- Mata老師確認的 GLOBAL LEARNING、MASTER SOP 或 QC 規範，必須同步至 GitHub。
- 同步內容至少包含正式規範文件與變更紀錄。
- 每次正式生成前，必須重新呼叫並讀取 GitHub 最新規範，不得只依賴聊天記憶。
- 若同步或讀取失敗，必須回報實際錯誤，不得先假設無法操作，也不得宣稱已同步。

## 6. Version Protection

- 本文件為全域補充規範，不覆寫既有 FINAL／LOCKED／MASTER 文件。
- 後續修改須建立 V1.1、V1.2 或 V2.0，不得直接覆寫本版本。
